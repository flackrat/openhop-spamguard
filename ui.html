        Spam sources

        Where spam entered the mesh over the last 7 days. Route codes are short and shared by many repeaters across the country, so SpamGuard follows each spam message's whole route back from your repeater, one radio hop at a time, and places each code at the repeater that fits the chain. It learns which repeater each code really is from the routes repeater adverts take to reach you, since an advert says exactly where it started. Spam from a repeater that never advertises (often the spammer's own) is placed from the known repeaters it hands the spam to.

        Repeaters messages arrived from

        Grouped by the first repeater on each route, over the detection window. “Never block” stops SpamGuard ever blocking that repeater automatically (useful for your own neighbours).

        Spam campaigns

        Groups of near-identical messages sent under different names. SpamGuard groups them even when words are added, capitals change or look-alike letters are swapped in.

        Exceptions

        Things SpamGuard should leave alone.

        Trusted senders

        Never counted as spam names and never de-duplicated. Channel names are not verified, so a spammer can copy a trusted name. SpamGuard still blocks a campaign even if one of its names is trusted, and logs a warning when a trusted name turns up somewhere new.

        Repeaters never blocked automatically

        Covers every hash width, so 27 also covers 27AB. You can still block these by hand.

        Text never blocked

        Messages containing any of these (capitals ignored) are never de-duplicated or treated as campaigns. Use for bots, net check-ins or regular announcements.

        Channels SpamGuard can read

        Spam on channels SpamGuard can't read is not detected. Hashtag channels only need the name, and you can paste several at once (e.g. #chat #test #amsterdam).

        Reading now

        In openHop's policy settings, not read yet . Add the ones SpamGuard should protect; their keys come from openHop, so there's nothing to type.

        Not re-blocked

        Blocks you removed by hand. SpamGuard won't re-create these for 24 hours.

        Evidence log

        A day-by-day record of every channel message SpamGuard reads, its spam signals, whether it was caught, and your “This is spam” / “Not spam” answers. Download it to review what happened, or to have SpamGuard's detection tuned against real traffic with the replay tool.

        Scrambled downloads replace every sender name (and @mentions of them) with a code, keeping each name's spam score and shape (e.g. AA9AAAAA), so the file can be shared without revealing who said what. Message text is kept.

            How SpamGuard works

            SpamGuard reads the channel messages your repeater hears and looks for the signs of a spammer: made-up names that change every message, lots of brand-new names arriving through one repeater, the same message sent under different names, and one name posting the same message over and over. Messages from this repeater's own companions are never blocked.

            When it finds spam it adds a rule to openHop so your repeater stops passing it on. It never changes your own openHop rules, and every automatic block ends by itself once the spam stops.

            openHop's packet list marks a dropped packet “Policy blocked packet (rule N)”. Each block on this page shows its openHop rule number, so you can see which block stopped it. In openHop's policy settings SpamGuard's rules are named after what they stop, with (yours) on blocks you added and (duplicate), (campaign), (repeating) or (auto) on ones SpamGuard made.

            Getting started

            SpamGuard starts on Monitor. Messages it would have stopped are marked “Would be stopped”. If it is only catching spam, switch to Protect. If you don't, it switches itself once it has watched for at least a day and seen enough spam (or after three quiet days), and says so in Activity. The Overview shows when; press Stay in Monitor to keep it watching only. It won't switch by itself if you have marked anything as Not spam.

            If it blocks someone genuine

            Press Not spam on their message. Their name is trusted from then on, and if a text block caught them, that block is removed. If a whole repeater was blocked, remove that block above. Busy events and people repeating the same message are the usual causes. Relaxed sensitivity makes both less likely.

            Limits

            SpamGuard only controls what your repeater forwards. People in direct range of the spammer will still hear him, so the more repeaters near the source run a filter, the better. It cannot read private channels or direct messages unless you give it the channel key. It never blocks a person for what they say: to hide someone you'd rather not read, use the block option in your own MeshCore app.

            Starting again

            Start again from scratch (Advanced, Settings) clears every block, setting and exception, and the page then shows only what happens after the reset. Nothing recorded is thrown away: the evidence log keeps everything.
